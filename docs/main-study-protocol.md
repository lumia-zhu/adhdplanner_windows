# 正式实验方案（Main Study Protocol）

## 1. 研究概述

- **研究范式**：Qualitative-dominant mixed-methods field study
- **研究周期**：约 2.5 周（Day 0 前测 + 14 天部署 + Day 15 后测访谈）
- **目标样本**：12–16 位具有 ADHD 诊断或显著执行功能困难的大学生
- **原型**：MetaPlan — 基于 GenAI 元认知支架的桌面任务管理工具

---

## 2. 研究问题

### Main RQ

**How does GenAI-based metacognitive scaffolding manifest in the everyday task management practices of people with executive function difficulties, and what design implications does it reveal?**

### Sub-RQ 1

How do people with executive function difficulties invoke, interpret, and negotiate GenAI-based metacognitive scaffolding in everyday task management?

### Sub-RQ 2

What key design principles and boundaries for GenAI-based metacognitive scaffolding are revealed through these use experiences?

---

## 3. 参与者

### 3.1 纳入标准

- 年龄 18–30 岁，在读大学生（本科或研究生）
- 满足以下任一条件：
  - 持有正式 ADHD 诊断
  - 自我报告存在显著执行功能困难（启动困难、注意力维持困难、任务切换频繁等）
- 日常有使用电脑处理学习/工作任务的习惯
- 使用 Windows 10/11 系统（64 位）

### 3.2 排除标准

- 无法连续使用电脑 2 周（如即将外出、设备不可用）
- 当前正处于严重心理健康危机中（由研究者在前访谈中评估）

### 3.3 招募渠道

- 校内 ADHD 互助群体 / 心理咨询中心推荐
- 社交媒体招募帖（小红书、豆瓣 ADHD 相关社区）
- 滚雪球（已参与者推荐）

### 3.4 背景信息记录

在 Pre-study Session 中收集：

| 类别 | 具体内容 |
|------|---------|
| 人口学 | 年龄、性别、年级、专业方向 |
| ADHD 背景 | 诊断时间、是否用药、主要困难类型（注意力/多动-冲动/混合） |
| 任务管理现状 | 目前使用的工具（纸笔/日历/待办应用/无固定工具）、自评效果 |
| 典型困难场景 | 启动难、中途卡住、忘记回顾、频繁切换（多选 + 自由补充） |

### 3.5 报酬

- 完成全部流程（前测 + 14 天使用 + 后测访谈）：¥XXX
- 中途退出按实际参与天数折算

```
Day 0          Pre-study Session
               ├── 知情同意

               ├── 后测量表（MAI-19 + SESRL）
               ├── 后访谈 + Trace Elicitation（~60–90 分钟）
               └── 收尾 & 报酬发放
```

## 5. Day 0: Pre-study Session

### 5.1 知情同意

- 说明研究目的、数据用途、参与者权利
- 强调：评估的是工具本身，不是参与者的能力或表现
- 告知数据存储方式（本地 + 云端加密）、匿名化处理
- 签署同意书

### 5.2 前测量表

| 量表 | 题数 | 量尺 | 用时 |
|------|:---:|------|:---:|
| MAI-19（任务管理改编版） | 19 | 5 点 Likert | ~5 分钟 |
| SESRL（任务管理改编版） | 9 | 7 点 Likert | ~3 分钟 |

### 5.3 前访谈：收集现有任务管理习惯（作为 baseline）

目标：了解参与者**在使用 MetaPlan 之前**的任务管理实践，作为后续分析"使用后发生了什么变化"的参照。

核心问题（约 20–30 分钟）：

**日常任务管理实践**

1. 你平时一天的学习/工作任务大概是什么样的？比如今天或昨天，你都做了哪些事？
2. 你平时是怎么决定"先做什么、后做什么"的？有没有用什么工具或方法？
3. 开始一个任务的时候，你通常是怎么启动的？比如打开电脑后，第一步一般会做什么？

**困难与应对**

4. 你觉得自己在管理任务时最大的困难是什么？可以举一个最近的例子吗？
5. 做任务做到一半卡住或者分心的时候，你通常会怎么处理？有什么自己的"招数"吗？
6. 一天结束的时候，你会不会回想今天做了什么、做得怎么样？如果会，通常是什么形式？

**对工具的期待**

7. 之前有没有试过用什么工具来帮自己管理任务？体验怎么样？最后为什么继续用/不用了？
8. 如果有一个工具能帮你管理任务，你最希望它帮你解决什么问题？

### 5.4 安装与 Onboarding

- 协助安装 MetaPlan（`MetaPlan Setup 1.0.0.exe`）
- 引导参与者完成一次完整流程体验：
  - 创建一个任务
  - 体验"启动第一步"
  - 简要了解"卡住求助"和"每日反思"功能的入口
- **原则**：只介绍功能位置和基本用法，不做深度引导，保留参与者自主探索空间
- 确认开机自启动已生效
- 建议参与者将电源设置调整为"盖上盖子不执行操作"（减少数据中断）

## 6. Day 1–14: 2-week Deployment

### 6.1 使用要求

- **自然使用**：在真实学习/工作场景中使用 MetaPlan 管理日常学习/工作任务
- **基础使用量**（保证分析所需的最低数据）：
  - 每周至少使用 MetaPlan 4 天
  - 每周至少完成 3 次反思对话
  - 每日微问卷回复率 ≥ 70%（14 天中至少 10 天）
- **自由使用所有功能**：任务管理、专注计时、启动第一步、卡住求助、每日反思均可自由使用，不限制使用方式和深度
- **弹性空间**：偶尔一两天没用完全可以理解——但如果连续 3 天以上未使用，研究者会联络确认情况

> **Onboarding 时向参与者说明**：这些要求是为了保证研究数据的完整性，不是为了评价你的表现。只要你在真实场景中使用它来管理任务，就已经是最有价值的数据了。

### 6.2 研究者角色

- **被动观察为主**：不主动提醒参与者使用某个功能
- **技术支持例外**：如参与者报告技术问题（安装失败、崩溃等），及时响应
- **基础使用量跟进**：通过后台数据监控参与者的使用情况，如低于基础使用量标准，适时友善提醒
  - 示例（微问卷漏填）："今天的小问卷还没填哦，就 1 分钟，方便的话帮忙填一下～"
  - 示例（长时间未使用）："这两天好像没怎么打开，是遇到什么问题了吗？还是最近比较忙？"
- **中期联络**（Day 7–8）：发一条简短消息确认使用情况和问题，不做内容引导
  - 示例："嗨，用了一周了，感觉怎么样？有没有遇到什么问题？技术上的或者使用上的都可以说～"

### 6.3 每日微问卷

每天推送一次（建议晚间 20:00–22:00），5 题 Likert（1–7 分），~1 分钟完成。

| # | 题目 | 对应维度 |
|:-:|------|---------|
| 1 | 今天我能清楚地知道自己要先做什么 | 计划（Forethought） |
| 2 | 今天做任务卡住时，我能想到办法继续 | 调节（Performance） |
| 3 | 今天我对自己的时间使用有比较清晰的感知 | 监控（Monitoring） |
| 4 | 今天我对自己完成任务的情况感到满意 | 评估（Self-reflection） |
| 5 | 今天使用 MetaPlan 对我管理任务有帮助 | 工具感知 |

**推送渠道**：微信问卷链接 / 问卷星小程序
**分析用途**：趋势图 + 访谈追问素材（"你第 3 天打了 2 分，第 8 天变成了 5 分，中间发生了什么？"）

### 6.4 异常处理

| 情况 | 处理方式 |
|------|---------|
| 连续 2 天未填微问卷 | 友善提醒，强调只需 1 分钟 |
| 一周内微问卷不足 5 天 | 联络确认原因，提供更方便的填写方式（如直接微信回复） |
| 连续 3 天未打开 MetaPlan | 简短询问是否遇到问题，记录原因，提供帮助 |
| 一周内任务记录 < 3 个 | 在中期联络时友善提及，了解是否因为使用困难 |
| 技术故障（崩溃/数据丢失） | 立即响应，记录故障信息，尽快修复 |
| 参与者主动要求退出 | 尊重决定，记录退出原因，按实际天数发放报酬 |
| 整体使用量严重不足（作为分析排除标准） | 如某参与者 14 天中有效使用天数 < 7 天，在分析时标注为 low-engagement 案例，单独讨论 |

## 7. Day 15: Post-study Session

### 7.1 后测量表

与前测相同：MAI-19（任务管理改编版）+ SESRL（任务管理改编版）

### 7.2 后访谈（含 Trace Elicitation）

时长：约 60–90 分钟，录音（征得同意）

**访谈结构：**

#### Part A: 整体回顾（10 分钟）

1. 这两周用下来，整体感觉怎么样？
2. 有没有哪个时刻让你觉得"这个挺有用"？可以说说当时的情况吗？
3. 有没有哪个时刻让你觉得"不想用了"或者"没什么帮助"？

#### Part B: Trace Elicitation — 结合数据回顾（30–40 分钟）

研究者提前从系统日志和 Dashboard 中提取参与者的关键使用片段，在访谈中逐个回顾。

准备方式：
- 从 Dashboard 导出参与者的使用数据
- 标记 3–5 个值得深入讨论的片段，例如：
  - 某天专注时长特别长或特别短
  - 多次触发"卡住"功能的日子
  - 反思对话特别深入的一次
  - 连续几天未使用的间断期

每个片段的追问框架：
- "这天的数据显示你 [描述行为]，你还记得当时的情况吗？"
- "当时你是怎么想的？"
- "AI 给的 [具体内容] 你后来是怎么处理的——用了、改了、还是没理它？"

#### Part C: 三个功能模块讨论（15–20 分钟）

对每个功能（启动第一步 / 卡住求助 / 每日反思），核心问三件事：
1. 你觉得它主要在帮你什么？
2. 什么时候它最有用，什么时候最没用？
3. 如果让你改一个地方，你会改什么？

#### Part D: 总结与展望（5–10 分钟）

1. 这两周下来，你觉得自己管理任务的方式有没有什么变化？不管是大的还是小的。
2. 如果之后没有这个工具了，有什么你想保留的做法或习惯吗？
3. 还有什么我们没问到但你想说的？

## 9. 数据分析方法

### 9.1 定性分析（主要）

- **方法**：Reflexive Thematic Analysis（Braun & Clarke, 2006, 2019）
- **编码流程**：
  1. 逐份转写 → 反复阅读 → 初始编码
  2. 按 RQ 组织编码 → 合并为候选主题
  3. 跨案例比较 → 提炼最终主题
  4. 回到原始数据验证

### 9.2 定量分析（辅助）

- MAI-19 / SESRL 前后对比：配对 t 检验或 Wilcoxon 符号秩检验（样本量较小时优先用非参数）
- 每日微问卷：5 题 × 14 天趋势图，观察变化方向
- 行为日志汇总指标：每日专注时长、任务完成率、卡住频次、反思触发次数等

### 9.3 三角互证

```
行为日志（"做了什么"）
      ↕
每日微问卷（"当天感受"）
      ↕
后访谈（"为什么这么做、怎么理解"）
```

## 10. 伦理与风险

### 10.1 伦理审查

- 提交校级 IRB / 人类受试者伦理委员会审批
- 研究不涉及医学干预，属于最低风险类别

### 10.2 知情同意要点

- 研究目的、流程和预计耗时
- 数据收集内容（行为日志、AI 对话痕迹、访谈录音）
- 数据存储方式：本地加密 + Supabase 云端（匿名化）
- 参与者可随时退出，数据将在退出后删除
- 研究结果不会包含可识别个人身份的信息

### 10.3 ADHD 参与者的特殊关怀

- 每日微问卷控制在 1 分钟以内
- 基础使用量要求设定在"保证分析可行"的最低线，不追求高强度使用
- 访谈中不使用评判性语言（"你为什么没用""你只做了…"）
- 如参与者表现出情绪困扰，提供校内心理支持资源信息

## 12. 预实验对本方案的影响

本方案将在 5 天预实验完成后，根据以下评估结果进行调整：

| 评估内容 | 可能的调整 |
|---------|----------|
| 量表灵敏度 | 如 MAI-19 或 SESRL 在 5 天内无变化信号，考虑替换或补充 |
| 微问卷区分度 | 删除区分度低的题目，或调整措辞 |
| 功能使用率 | 如某功能在预实验中几乎无人使用，评估是否需要调整入口设计 |
| 参与者反馈 | 量表题目是否清晰、填写负担是否可接受、onboarding 是否充分 |
| 技术稳定性 | 修复预实验中暴露的崩溃、数据丢失等问题 |
