# 反思 Tag 文案优化与分类

## 文档目的

这份文档整理「数据可视化反思」底部 Tag 的文案优化方向，目标是让 Tag 更像自然聊天里的问题，少一些研究感、系统感和评价感。

Tag 的产品定位：

- 帮用户选择一个想看的分析方向。
- 不直接下结论。
- 不把图表名当入口。
- 不让用户感觉被评价、被追责。

## 文案优化表

| 修改前 | 修改后 | 修改原因 |
|---|---|---|
| 卡顿密集任务 | 容易卡住的任务 | “密集”偏数据分析口吻，“容易卡住”更像用户自己的感受。 |
| 分析卡顿情况 | 想看看哪里不顺吗？ | “分析”有压力，“哪里不顺”更口语，也更像邀请。 |
| 卡住时正在做什么 | 卡住时卡在哪一步？ | “正在做什么”太宽泛，“卡在哪一步”更具体。 |
| 总被留到后面的事 | 哪些事总被放到后面？ | “被留到后面”不够口语，“放到后面”更自然。 |
| 反复出现在计划里的任务 | 哪些任务反复出现？ | 原句太长，“反复出现”足够表达模式。 |
| 和前几天的区别 | 和前几天哪里不一样？ | “区别”偏书面，“哪里不一样”更像聊天。 |
| 两天的节奏 | 这两天节奏有什么不一样？ | 比“节奏一样吗”更开放，不会变成是/否问题。 |
| 这周多出来的任务 | 这周多了哪些任务？ | 更像用户能直接理解的问题。 |
| 这周少掉的任务 | 这周少了哪些任务？ | 更自然，减少“掉”的怪异感。 |
| 比较活跃的时段 | 哪些时间更容易动起来？ | “活跃时段”偏图表语言，“动起来”更贴近 ADHD 启动体验。 |
| 比较集中的推进时间 | 哪些时间效率较高？ | “推进时间”研究感强，“效率较高”更接近日常复盘里想找的有效时段。 |
| 电脑开着时在做什么 | 电脑开着时都在做什么？ | 加“都”更口语。 |
| 活动最密的时间在做什么 | 最忙那段都在忙什么？ | “活动最密”太数据化，“最忙那段”更自然。 |
| 列了但没开始的事 | 哪些任务列了但没开始？ | 明确对象是任务，避免句子太省略。 |
| 很快勾掉的任务 | 哪些任务很快就做完了？ | “勾掉”偏系统操作，“做完”更贴近用户理解。 |
| 花最久的任务 | 哪个任务花了最多时间？ | 更像自然问题。 |
| 顺手做完的任务 | 哪些任务做起来比较顺？ | “顺手做完”有点奇怪，“做起来比较顺”更自然。 |
| 被留到后面的事 | 哪些事被放到后面了？ | 更口语。 |
| 任务用时排行 | 哪些任务最花时间？ | 避免图表名，直接说用户关心的问题。 |
| 停下来的那一步 | 是哪一步让你停住了？ | 更像用户能回答的问题。 |
| 卡住后怎么继续的 | 卡住后是怎么接回来的？ | “接回来”更贴近任务连续性。 |

## Tag 分类建议

不建议在用户界面里显示“正面 / 负面”这类分类，因为这会让 Tag 本身带评价感。

内部可以分成三类：

- **有效经验类**：帮助用户先看到哪些做法值得保留、哪些条件更容易推进。
- **卡点观察类**：帮助用户看到哪里不顺、哪里容易卡住，但语气要轻。
- **中性探索类**：不预设好坏，只帮助用户看变化、对比或任务分布。

### 有效经验类

| Tag | 判断理由 |
|---|---|
| 哪些做法值得保留？ | 直接引导用户提炼可复用经验。 |
| 哪些时间更容易动起来？ | 帮用户发现更容易开始/行动的时间。 |
| 哪些时间效率较高？ | 帮用户看到更容易有效推进的时段。 |
| 哪些任务很快就做完了？ | 指向容易完成、阻力较低的任务。 |
| 哪些任务做起来比较顺？ | 直接指向顺利推进的任务。 |
| 卡住后是怎么接回来的？ | 虽然有卡住，但重点是恢复和重新接上。 |

### 卡点观察类

| Tag | 判断理由 |
|---|---|
| 容易卡住的任务 | 指向任务阻力和反复卡住。 |
| 想看看哪里不顺吗？ | 明确邀请看不顺的地方，但语气比较轻。 |
| 卡住时卡在哪一步？ | 指向具体卡点。 |
| 哪些事总被放到后面？ | 指向回避、延后或优先级冲突。 |
| 哪些任务还停在计划里？ | 指向计划和执行之间的断点，比“没开始”更柔和。 |
| 是哪个步骤让你停住了？ | 指向停止点和阻力来源。 |

### 中性探索类

| Tag | 判断理由 |
|---|---|
| 哪些任务反复出现？ | 可以是持续推进，也可以是长期卡住，点开后再判断。 |
| 和前几天哪里不一样？ | 只是对比变化，不预设好坏。 |
| 这两天节奏有什么不一样？ | 只是比较节奏差异。 |
| 这周多了哪些任务？ | 任务数量变化，不直接正负。 |
| 这周少了哪些任务？ | 任务数量变化，不直接正负。 |
| 电脑开着时都在做什么？ | 观察电脑活动内容，不预设评价。 |
| 最忙那段都在忙什么？ | 观察高活动时段，不直接判断好坏。 |
| 哪个任务花了最多时间？ | 用时长短不一定好坏。 |
| 哪些任务最花时间？ | 属于任务分布观察。 |
| 哪些事被放到后面了？ | 可以是正常调整，也可能是卡点，需要点开后判断。 |

## 生成策略建议

每次生成 3 个 Tag 时，建议尽量搭配：

1. 1 个有效经验类，例如「哪些做法值得保留？」
2. 1 个卡点观察类，例如「哪些任务还停在计划里？」
3. 1 个中性探索类，例如「和前几天哪里不一样？」

有效经验类建议尽量放在第一个。这样用户不会一打开就全是“哪里不顺”“哪里卡住”，而是先看到自己做对和可以保留的部分。

---

## 文案原则

- 尽量使用问题式，如“哪些任务最花时间？”。
- 少用“分析”“密集”“推进”“入口”“实际”等研究感词。
- 少用容易评价用户的表达，如“一直没碰”“没动”“效率低”。
- 不要把图表名当作 Tag，如“任务用时排行”“电脑活动图”。
- 不要写半截话，如“卡住后的那段”“后来接上的地方”。
- 不要提前下结论，如“完成得很顺”“任务切得刚好”。
