# ADHD 原型 Memory 方案

## 文档目的

这份文档用于梳理当前原型中引入 `memory` 的设计方案，重点不是让 AI “记住用户的一切”，而是帮助用户在反思过程中逐渐看见自己的任务管理模式、尝试过的策略，以及跨时间形成更稳定的自我理解。

当前原型的三个核心功能点为：

1. `启动第一步`
2. `任务过程中卡住求助`
3. `数据可视化支持的反思`

---

## 为什么需要 Memory

当前系统中，每一天的反思对话基本是相互独立的：

- AI 不知道昨天聊了什么
- AI 不知道用户昨天说过想尝试什么调整
- AI 不知道用户是否反复在同一个地方卡住
- AI 不知道哪些建议对这个用户更有效
- AI 也没有真正利用已有的用户画像信息

这会带来几个问题：

- 用户很难意识到自己反复出现的模式
- 反思里的“明天我想试试……”无法形成闭环
- AI 每次都像第一次认识用户，容易重复和同质化
- 用户不容易看见自己的进步或长期变化

因此，Memory 的目标不是单纯增加 AI 的上下文，而是支持更长期的元认知反思。

---

## Memory 要解决的元认知问题

### 1. 帮助用户识别重复模式

例如：

- 我是不是总在开始之前就卡住？
- 我是不是经常在任务太大时停下来？
- 我是不是在某些时间段更容易进入状态？

Memory 可以帮助 AI 在多天数据中发现这些模式，并在反思时自然指出。

### 2. 帮助用户回顾反思后的承诺有没有落地

例如：

- 昨天说“明天先从最简单的任务开始”，今天有没有做到？
- 昨天说“卡住时立刻求助”，今天有没有真的使用这个功能？

Memory 可以让反思不只是回顾过去，而是形成“回顾 - 尝试 - 再回顾”的闭环。

### 3. 帮助用户看见自己的成长

例如：

- 这周卡住次数比上周少了
- 更容易开始任务了
- 开始学会主动使用某些支持功能了

这能帮助用户减少“我一直都不行”的感觉。

### 4. 帮助 AI 逐渐个性化

例如：

- 这个用户更喜欢简短直接的提示
- 这个用户更适合“先动起来”的策略
- 这个用户不喜欢太多解释和过长的反思问题

这样 AI scaffolding 才能越来越贴合个人，而不是每次都从零猜。

---

## Memory 的设计目标

Memory 系统的核心目标可以概括为：

1. 帮助用户跨时间地看见自己的任务管理模式
2. 帮助用户把反思中的想法转化为下一次行动
3. 帮助 AI 逐步理解什么支持方式更适合这个用户
4. 为周反思和长期使用提供更连贯的支持
5. 在不增加明显负担和风险的前提下提升个性化程度

---

## 建议的 Memory 类型

相比只按“日级记忆 / 周级记忆”来分，更建议按“记忆的功能”来构建。

### 1. Pattern Memory

记录反复出现的规律。

例如：

- 经常在开始任务前卡住
- 任务太大时容易停下来
- 下午更容易进入状态
- 有任务记录，但完成率波动较大

这类记忆主要用于帮助用户识别长期模式。

### 2. Strategy Memory

记录对这个用户真正有效的方法。

例如：

- “先打开文档”这类第一步更容易被采纳
- 卡住时更适合给绕路建议，而不是继续解释原因
- 更容易回应简短的引导问题

这类记忆主要用于帮助 AI 提供更适合这个人的支持方式。

### 3. Commitment Memory

记录用户在反思中明确说过的“明天想试什么”。

例如：

- 明天先从最简单的部分开始
- 明天先做 10 分钟
- 如果卡住就直接点求助

这类记忆主要用于形成反思到下一次行动的闭环。

### 4. Preference Memory

记录用户更喜欢怎样被帮助。

例如：

- 喜欢简短直接的建议
- 不喜欢太多图表
- 不喜欢被频繁提醒
- 更愿意接受具体动作，而不是抽象鼓励

这类记忆主要用于降低交互负担，提升自然使用的可能性。

## Memory 的构建原则

为了避免 Memory 变得太重、太冒犯或太容易出错，建议遵循以下原则：

### 原则 1：Memory 是辅助假设，不是事实判断

AI 不应该把记忆当作确定结论，而应该用更温和、试探性的方式表达。

例如：

- 更合适：`最近几次里，你好像常常会在任务太大时停下来，不知道你自己会不会也有这种感觉？`
- 不合适：`你总是因为不会拆任务所以卡住。`

### 原则 2：只有重复出现或用户明确表达的内容才写入 Memory

不要因为一次对话里提到一句，就长期记住。

更适合写入的情况：

- 同一种模式连续出现 2-3 次
- 用户明确说出“明天我想试……”
- 用户多次表现出明显的偏好

### 原则 3：Memory 要允许衰减和更新

不是所有记忆都应该永久保留。

例如：

- 承诺记忆只保留最近几条
- 很久没出现的模式逐渐降权
- 偏好允许被覆盖和更新

### 原则 4：Memory 应该可见、可删、可纠正

用户应当能够看到系统记住了什么，并在必要时删除或修正。

### 原则 5：优先使用结构化 Memory，而不是大量长文本记忆

早期方案建议优先做小而明确的结构化字段，而不是直接长期保存很多原始对话摘要并做复杂检索。

---

## 建议的架构

### A. Raw Evidence Layer

底层证据层，不直接给 AI 使用。

来源可以包括：

- 每日任务数据
- tracker events
- 活跃度数据
- 反思对话
- 卡住求助交互
- 启动第一步建议是否被采纳

作用：

- 为 Memory 生成提供依据
- 便于研究分析与后续回溯

### B. Structured Memory Layer

真正给 AI 使用的结构化记忆层。

建议的数据结构：

```ts
interface UserMemory {
  patterns: MemoryItem[]
  strategies: MemoryItem[]
  commitments: MemoryItem[]
  preferences: MemoryItem[]
}

interface MemoryItem {
  id: string
  text: string
  confidence: number
  sourceDates: string[]
  lastUpdated: number
  decayScore: number
}
```

### C. Retrieval Layer

每次反思时，不把全部记忆都塞给 AI，而是只取最相关的几条。

例如：

- 日反思开始时：
  - 最近承诺 1-2 条
  - 相关模式 1-2 条
  - 偏好 1 条
- 卡住求助时：
  - 相关模式 1-2 条
  - 过去有效策略 1-2 条
- 周反思时：
  - 本周高频模式
  - 本周成长变化
  - 最常见有效策略

## 在三个核心功能中的具体价值

## 1. 启动第一步

Memory 能帮助 AI 不只是围绕“今天要开始什么任务”给建议，还能结合过去经验判断：

- 用户通常在哪种任务上最难开始
- 用户更容易接受哪种类型的第一步
- 用户是否总在“决定从哪开始”这一步卡住

这样“启动第一步”会越来越个性化。

## 2. 任务过程中卡住求助

Memory 能帮助 AI 不只是接住当下，还能指出：

- 这次卡住是不是和最近几次属于同一种模式
- 哪种建议方式过去更有效
- 用户更适合“重新聚焦”、还是“绕路”、还是“降门槛”

这会让卡住求助不只是一次性急救，而是慢慢帮助用户理解自己为什么会卡。

## 3. 数据可视化支持的反思

Memory 能帮助每日和每周反思做到：

- 跟进昨天说过的话
- 指出这一周反复出现的模式
- 看见进步而不只是看见问题
- 让反思问题更不重复、更贴近用户自己的情况

---

## 推荐的实现优先级

### Phase 1：轻量 Memory

优先做：

1. `Profile 注入`
2. `Commitment Memory`
3. `Pattern Memory v1`

这一阶段的目标是先形成最基本的反思闭环，并让 AI 具备有限但稳定的跨天连续性。

### Phase 2：策略个性化

加入：

1. `Strategy Memory`
2. 更细的 Pattern 分类
3. 更合适的检索逻辑

这一阶段的目标是让 AI 不只是“记住”，而是逐渐知道什么支持方式对这个用户更有效。

### Phase 3：长期陪伴与可见性

加入：

1. `Weekly Memory`
2. Memory 可视化或可编辑面板
3. 用户可删除、纠正 Memory 的机制

这一阶段的目标是支持更长期的使用与更稳妥的伦理边界。

---

## 第一版最值得先做的内容

如果当前只想做一个最小可用版本，建议优先从下面三项开始：

1. 把已有的 `UserProfile` 注入反思 prompt
2. 在日反思结束后提取 `Commitment Memory`
3. 记录最简单的 `Pattern Memory`，例如：
   - 启动困难
   - 任务太大
   - 容易分心

这是因为这三项：

- 实现成本相对低
- 对反思闭环帮助最直接
- 风险可控
- 也最适合用于后续用户研究观察

---

## 一个更清晰的总定义

Memory 不是为了让 AI “长期记住用户”，而是为了帮助用户跨时间地看见：

- 自己反复出现的模式
- 对自己有效的策略
- 自己说过想尝试的调整
- 自己的变化与成长

从这个角度看，Memory 的价值不只是个性化，而是更长期的元认知支持。
