# ADHD 原型 Memory 方案

## 文档目的

这份文档用于梳理当前原型中引入 `memory` 的设计方案，重点不是让 AI “记住用户的一切”，而是帮助用户在反思过程中逐渐看见自己的任务管理模式、尝试过的策略，以及跨时间形成更稳定的自我理解。

当前原型的三个核心功能点为：

1. `启动第一步`
2. `任务过程中卡住求助`
3. `数据可视化支持的反思`

---

## 为什么需要 Memory

当前系统中，每一天的反思对话基本是相互独立的：

- AI 不知道昨天聊了什么
- AI 不知道用户昨天说过想尝试什么调整
- AI 不知道用户是否反复在同一个地方卡住
- AI 不知道哪些建议对这个用户更有效
- AI 也没有真正利用已有的用户画像信息

这会带来几个问题：

- 用户很难意识到自己反复出现的模式
- 反思里的“明天我想试试……”无法形成闭环
- AI 每次都像第一次认识用户，容易重复和同质化
- 用户不容易看见自己的进步或长期变化

因此，Memory 的目标不是单纯增加 AI 的上下文，而是支持更长期的元认知反思。

---

## Memory 要解决的元认知问题

### 1. 帮助用户识别重复模式

例如：

- 我是不是总在开始之前就卡住？
- 我是不是经常在任务太大时停下来？
- 我是不是在某些时间段更容易进入状态？

Memory 可以帮助 AI 在多天数据中发现这些模式，并在反思时自然指出。

### 2. 帮助用户回顾反思后的承诺有没有落地

例如：

- 昨天说“明天先从最简单的任务开始”，今天有没有做到？
- 昨天说“卡住时立刻求助”，今天有没有真的使用这个功能？

Memory 可以让反思不只是回顾过去，而是形成“回顾 - 尝试 - 再回顾”的闭环。

### 3. 帮助用户看见自己的成长

例如：

- 这周卡住次数比上周少了
- 更容易开始任务了
- 开始学会主动使用某些支持功能了

这能帮助用户减少“我一直都不行”的感觉。

### 4. 帮助 AI 逐渐个性化

例如：

- 这个用户更喜欢简短直接的提示
- 这个用户更适合“先动起来”的策略
- 这个用户不喜欢太多解释和过长的反思问题

这样 AI scaffolding 才能越来越贴合个人，而不是每次都从零猜。

---

## Memory 的设计目标

Memory 系统的核心目标可以概括为：

1. 帮助用户跨时间地看见自己的任务管理模式
2. 帮助用户把反思中的想法转化为下一次行动
3. 帮助 AI 逐步理解什么支持方式更适合这个用户
4. 为周反思和长期使用提供更连贯的支持
5. 在不增加明显负担和风险的前提下提升个性化程度

---

## Memory 的总体定位

`Memory` 不应只是“让 AI 记住用户”，而应成为三个阶段之间的连接层：

- 在计划阶段，帮助系统更了解“这个人通常怎么开始任务、会在哪一步犹豫”
- 在执行阶段，帮助系统识别“这次卡住是不是重复模式、过去什么支持更有效”
- 在反思阶段，帮助系统把“今天发生了什么”放进更长的时间线里，让用户逐渐看见自己的稳定模式、变化和成长

它的核心价值不是单纯增加模型上下文，而是支持用户形成跨时间的元认知：**看清任务、看清自己、看清策略、看清规律。**

---

## 三个阶段各自的目标

### 1. 计划阶段

目标：降低启动阻力，帮助用户更快进入“第一步”。

Memory 在这里更适合记住：

- 用户在哪类任务上更容易迟疑或拖延
- 用户过去更容易采纳哪种“第一步”建议
- 用户是更适合具体动作型支持，还是更适合降低门槛型支持

这一阶段的设计重点是：

- 优先使用轻量的 `Pattern Memory` 和 `Strategy Memory`
- 不需要展示太多历史信息，而是让系统在后台用这些记忆把“第一步建议”变得更贴人
- 目标不是给更复杂的建议，而是给“更像这个人会接受的建议”

### 2. 执行阶段

目标：在卡住、中断、恢复这些关键时刻，帮助用户更快回到行动。

Memory 在这里更适合记住：

- 这个用户常见的卡住类型
- 哪类绕路方式过去更常被接受
- 卡住通常发生在开始、中段还是收尾
- 用户更偏好被安抚、被具体指导，还是被提醒先缩小一步

这一阶段的设计重点是：

- 优先调取最近的 `Pattern Memory` 和 `Strategy Memory`
- 不把 memory 做成“AI 长篇分析”，而是只用于让 stuck 支持更快、更具体、更低负担
- 它更像一个“急救经验库”，帮助系统在当下给出更合适的支架

### 3. 反思阶段

目标：把行为痕迹转化为用户能看懂、能感受到、能带走一点东西的长期觉察。

Memory 在这里更适合记住：

- 反复出现的行为模式（如总在某时段活跃、总在某类任务上断掉）
- 用户在过去反思里提到过的解释、承诺和尝试
- 已经验证过的有效策略
- 用户是更愿意看趋势、看任务、看状态，还是看卡住点

这一阶段的设计重点是：

- 最适合同时使用 `Pattern Memory`、`Commitment Memory`、少量 `Strategy Memory`
- memory 不应直接替用户下结论，而应帮助 AI 温和地指出“这好像是最近反复出现的现象”
- 反思不应只是单天闭环，而应是“今天的数据”与“过去的自己”之间的对照面

---

## 为什么反思阶段特别重要

反思阶段是三个阶段中最适合沉淀长期价值的地方，因为这里既有：

- 来自计划和执行阶段的真实行为痕迹
- 用户已经结束任务后的相对低压力时刻
- 最适合把“发生了什么”转化为“我以后怎么看待这类情况”的机会

因此，数据可视化支持的反思部分不应只是“展示结果”，而应帮助用户逐渐完成四层变化：

- 情绪层：减少“我今天又不行”的模糊自责，先让用户看到真实发生了什么
- 觉察层：帮助用户看见平时不会主动注意到的时段、节奏、卡住与恢复模式
- 解释层：把“我感觉今天状态怪怪的”变成可以讨论的具体现象
- 调节层：慢慢沉淀出“下次要保留什么、提前注意什么、继续观察什么”

---

## 数据可视化反思部分的目标

这部分不应只是“展示图表 + 聊天”，而应承担三个目标：

### 1. 帮用户看到当天 / 这周最值得看的现象

不是堆很多图，而是帮助用户快速知道：

- 今天最有代表性的节奏是什么
- 这周最明显的趋势是什么
- 哪张图最值得点进去看

### 2. 帮用户把现象变成模式

也就是从“发生了什么”走到：

- 这只是偶然，还是反复出现？
- 这更像任务问题、状态问题，还是策略问题？
- 这和过去几次是否相似？

### 3. 帮用户带走一点长期有用的东西

不是每次都要明确给建议，而是至少沉淀为以下之一：

- 一个稳定规律
- 一个待验证的假设
- 一个值得保留的做法
- 一个下次继续观察的点

一句话说，这部分的目标不是帮助用户评价自己“今天做得好不好”，而是帮助用户基于真实行为数据，识别任务推进、状态变化与策略使用中的关键模式。

---

## 日反思与周反思的 Memory 角色应当不同

### 日反思

更适合回答：

- 今天到底发生了什么
- 今天哪段时间 / 哪个环节最值得看
- 今天的卡住和推进是怎么形成的

更适合调取的 memory：

- 最近 1-3 天的相似模式
- 昨天或最近一次说过的承诺
- 最近最有效的一种策略

### 周反思

更适合回答：

- 哪几天状态最好 / 最差
- 哪类模式在一周内反复出现
- 是否出现了变化趋势或进步
- 本周最值得带走的长期认识是什么

更适合调取的 memory：

- 本周高频 `Pattern Memory`
- 本周策略效果对比
- 上周或更早的粗粒度趋势

一句话总结：

- 日反思偏“解释单日现象”
- 周反思偏“识别跨天规律”

---

## 反思阶段最值得优先构建的 Memory

如果只做一个轻量但真正有价值的版本，反思阶段最值得优先构建的是：

### 1. Pattern Memory

用于帮助用户看见反复出现的模式，例如：

- 下午更容易进入状态
- 任务太大时更容易停住
- 活跃度很高，但不一定真的进入专注

### 2. Commitment Memory

用于形成反思到下一次行动的闭环，例如：

- 明天先从最简单的部分开始
- 如果卡住就直接点求助
- 明天先做 10 分钟，不要求做完

### 3. 少量 Strategy Memory

早期可以先只保留最明确、最有证据的一两条，例如：

- 先打开文档比先列提纲更容易开始
- 绕路型建议比解释型建议更容易被采纳

之所以优先顺序是这样，是因为：

- `Pattern Memory` 最直接支持“看见重复模式”
- `Commitment Memory` 最直接支持“形成反思闭环”
- `Strategy Memory` 更适合在后续逐步增强个性化时补上

---

## 现阶段最合适的大致方向

如果当前还不着急进入实现细节，而是先从产品与研究价值上把方向定清楚，我更建议这样理解三者分工：

- 左侧数据可视化负责“把行为现象摆出来”
- 右侧 AI 对话负责“帮助理解这个现象可能意味着什么”
- `Memory` 负责“把今天看到的东西接到过去和未来上”

这样一来，反思区就不再只是一个结束页，而会成为整个原型里最能支持长期元认知积累的部分。

## 建议的 Memory 类型

相比只按“日级记忆 / 周级记忆”来分，更建议按“记忆的功能”来构建。

### 1. Pattern Memory

记录反复出现的规律。

例如：

- 经常在开始任务前卡住
- 任务太大时容易停下来
- 下午更容易进入状态
- 有任务记录，但完成率波动较大

这类记忆主要用于帮助用户识别长期模式。

### 2. Strategy Memory

记录对这个用户真正有效的方法。

例如：

- “先打开文档”这类第一步更容易被采纳
- 卡住时更适合给绕路建议，而不是继续解释原因
- 更容易回应简短的引导问题

这类记忆主要用于帮助 AI 提供更适合这个人的支持方式。

### 3. Commitment Memory

记录用户在反思中明确说过的“明天想试什么”。

例如：

- 明天先从最简单的部分开始
- 明天先做 10 分钟
- 如果卡住就直接点求助

这类记忆主要用于形成反思到下一次行动的闭环。

### 4. Preference Memory

记录用户更喜欢怎样被帮助。

例如：

- 喜欢简短直接的建议
- 不喜欢太多图表
- 不喜欢被频繁提醒
- 更愿意接受具体动作，而不是抽象鼓励

这类记忆主要用于降低交互负担，提升自然使用的可能性。

---

## Memory 的构建原则

为了避免 Memory 变得太重、太冒犯或太容易出错，建议遵循以下原则：

### 原则 1：Memory 是辅助假设，不是事实判断

AI 不应该把记忆当作确定结论，而应该用更温和、试探性的方式表达。

例如：

- 更合适：`最近几次里，你好像常常会在任务太大时停下来，不知道你自己会不会也有这种感觉？`
- 不合适：`你总是因为不会拆任务所以卡住。`

### 原则 2：只有重复出现或用户明确表达的内容才写入 Memory

不要因为一次对话里提到一句，就长期记住。

更适合写入的情况：

- 同一种模式连续出现 2-3 次
- 用户明确说出“明天我想试……”
- 用户多次表现出明显的偏好

### 原则 3：Memory 要允许衰减和更新

不是所有记忆都应该永久保留。

例如：

- 承诺记忆只保留最近几条
- 很久没出现的模式逐渐降权
- 偏好允许被覆盖和更新

### 原则 4：Memory 应该可见、可删、可纠正

用户应当能够看到系统记住了什么，并在必要时删除或修正。

### 原则 5：优先使用结构化 Memory，而不是大量长文本记忆

早期方案建议优先做小而明确的结构化字段，而不是直接长期保存很多原始对话摘要并做复杂检索。

---

## 建议的架构

### A. Raw Evidence Layer

底层证据层，不直接给 AI 使用。

来源可以包括：

- 每日任务数据
- tracker events
- 活跃度数据
- 反思对话
- 卡住求助交互
- 启动第一步建议是否被采纳

作用：

- 为 Memory 生成提供依据
- 便于研究分析与后续回溯

### B. Structured Memory Layer

真正给 AI 使用的结构化记忆层。

建议的数据结构：

```ts
interface UserMemory {
  patterns: MemoryItem[]
  strategies: MemoryItem[]
  commitments: MemoryItem[]
  preferences: MemoryItem[]
}

interface MemoryItem {
  id: string
  text: string
  confidence: number
  sourceDates: string[]
  lastUpdated: number
  decayScore: number
}
```

### C. Retrieval Layer

每次反思时，不把全部记忆都塞给 AI，而是只取最相关的几条。

例如：

- 日反思开始时：
  - 最近承诺 1-2 条
  - 相关模式 1-2 条
  - 偏好 1 条
- 卡住求助时：
  - 相关模式 1-2 条
  - 过去有效策略 1-2 条
- 周反思时：
  - 本周高频模式
  - 本周成长变化
  - 最常见有效策略

## 在三个核心功能中的具体价值

## 1. 启动第一步

Memory 能帮助 AI 不只是围绕“今天要开始什么任务”给建议，还能结合过去经验判断：

- 用户通常在哪种任务上最难开始
- 用户更容易接受哪种类型的第一步
- 用户是否总在“决定从哪开始”这一步卡住

这样“启动第一步”会越来越个性化。

## 2. 任务过程中卡住求助

Memory 能帮助 AI 不只是接住当下，还能指出：

- 这次卡住是不是和最近几次属于同一种模式
- 哪种建议方式过去更有效
- 用户更适合“重新聚焦”、还是“绕路”、还是“降门槛”

这会让卡住求助不只是一次性急救，而是慢慢帮助用户理解自己为什么会卡。

## 3. 数据可视化支持的反思

Memory 能帮助每日和每周反思做到：

- 跟进昨天说过的话
- 指出这一周反复出现的模式
- 看见进步而不只是看见问题
- 让反思问题更不重复、更贴近用户自己的情况

---

## 推荐的实现优先级

### Phase 1：轻量 Memory

优先做：

1. `Profile 注入`
2. `Commitment Memory`
3. `Pattern Memory v1`

这一阶段的目标是先形成最基本的反思闭环，并让 AI 具备有限但稳定的跨天连续性。

### Phase 2：策略个性化

加入：

1. `Strategy Memory`
2. 更细的 Pattern 分类
3. 更合适的检索逻辑

这一阶段的目标是让 AI 不只是“记住”，而是逐渐知道什么支持方式对这个用户更有效。

### Phase 3：长期陪伴与可见性

加入：

1. `Weekly Memory`
2. Memory 可视化或可编辑面板
3. 用户可删除、纠正 Memory 的机制

这一阶段的目标是支持更长期的使用与更稳妥的伦理边界。

---

## 第一版最值得先做的内容

如果当前只想做一个最小可用版本，建议优先从下面三项开始：

1. 把已有的 `UserProfile` 注入反思 prompt
2. 在日反思结束后提取 `Commitment Memory`
3. 记录最简单的 `Pattern Memory`，例如：
   - 启动困难
   - 任务太大
   - 容易分心

这是因为这三项：

- 实现成本相对低
- 对反思闭环帮助最直接
- 风险可控
- 也最适合用于后续用户研究观察

---

## 一个更清晰的总定义

Memory 不是为了让 AI “长期记住用户”，而是为了帮助用户跨时间地看见：

- 自己反复出现的模式
- 对自己有效的策略
- 自己说过想尝试的调整
- 自己的变化与成长

从这个角度看，Memory 的价值不只是个性化，而是更长期的元认知支持。
