# 情绪数据可视化设计思路

这个文档记录「每日心情记录」后续如何放进数据可视化图表里。重点不是证明“情绪决定效率”，而是帮助用户看见：自己在不同状态下，怎样开始、推进、卡住、恢复。

## 一句话目标

情绪数据只用来帮助用户理解自己的状态背景和支持需求，不用来判断效率高低，也不用来解释成败原因。

更简单地说：它像天气记录，不是成绩单。

## 为什么要把情绪放进图表

当前任务图表主要回答：

| 图表问题 | 用户看到的是 |
|---|---|
| 今天完成了多少任务？ | 任务完成率、完成数量 |
| 哪些时间电脑更活跃？ | 活跃时间段、使用节奏 |
| 哪些任务花了最多时间？ | 任务用时排行 |

加入情绪后，可以多回答一层：

| 新问题 | 设计价值 |
|---|---|
| 我是在什么状态下完成这些事的？ | 让结果有背景，不只是数字。 |
| 状态不好时，我有没有仍然推进一点？ | 帮用户看见自己仍然有能力。 |
| 哪些状态下我更容易开始？ | 找到适合自己的启动方式。 |
| 卡住后，我通常能不能回来？ | 找到恢复任务的经验。 |

## 核心产品原则

| 原则 | 说明 | 避免什么 |
|---|---|---|
| 情绪是背景，不是评价 | 心情记录用于解释当天状态，不用于给用户打分。 | 避免说“低落所以效率低”。 |
| 只提示相关性，不暗示因果 | 图表只能说“这几天同时出现了什么”，不能说“因为心情导致了什么”。 | 避免把情绪当成任务结果的原因。 |
| 多看启动和恢复，不只看完成率 | ADHD 用户的关键困难常常是开始和卡住后回来。 | 避免只用完成率衡量一天。 |
| 用温和语言表达 | 文案要像回看状态，而不是绩效分析。 | 避免“表现最好/最差”。 |
| 样本少时要说明 | 如果某种心情只覆盖 1 天，就不能当成稳定规律。 | 避免用户误读为长期模式。 |

## 推荐观察角度

| 观察角度 | 想回答的问题 | 可结合的数据 |
|---|---|---|
| 情绪 × 完成率 | 不同状态下，任务结果大概怎样？ | 每日心情、每日任务完成率、完成任务数、总任务数 |
| 情绪 × 启动率 | 不同状态下，我能不能开始？ | 每日心情、是否开始过任务、第一个任务开始时间 |
| 情绪 × 卡住/恢复 | 不同状态下，我卡住后能不能回来？ | 每日心情、卡住次数、卡住原因、卡住后是否继续任务 |
| 情绪 × 活跃节奏 | 不同状态下，我通常在什么时间段更能动起来？ | 每日心情、电脑活跃分布、任务发生时间段 |

## 可视化方案 1：每日完成率 + 心情折线

这是最直观、最适合第一版的做法。

### 图表结构

| 元素 | 表示什么 |
|---|---|
| 柱子高度 | 当天任务完成率 |
| 柱子颜色 | 当前实现统一使用单色柱子，避免颜色和高度同时表达不同含义 |
| 右侧纵轴 | 1–5 级心情，1 表示很低落，5 表示很开心 |
| 心情折线 | 真实心情优先；未记录心情的日期用示例心情补齐，让 7 天都有点和连续折线 |
| 百分比标签 | 独立显示在最上层，并略高于柱顶，避免被心情折线或圆点遮挡 |
| 日期和星期 | 帮用户回忆当天 |
| Tooltip | 完成任务数、总任务数、心情文字、心情备注 |

### 它回答的问题

| 用户问题 | 图表能帮助看到什么 |
|---|---|
| 这周哪几天完成得比较多？ | 每天完成率变化。 |
| 那几天我是什么状态？ | 每天对应的心情背景。 |
| 有没有状态低但仍然推进的日子？ | 低落心情下仍然完成任务的例子。 |

### 示例解释

| 情况 | 更合适的解释方式 | 不建议的解释方式 |
|---|---|---|
| 很低落 + 完成率 70% | “那天状态不轻松，但仍然推进了不少。” | “虽然低落但效率还可以。” |
| 很开心 + 完成率 25% | “开心不一定等于任务推进，可能那天有别的安排。” | “开心也没完成好。” |
| 平静 + 完成率 100% | “平静状态下可能更容易稳定执行，值得后续观察。” | “平静会让你效率最高。” |

## 可视化方案 2：不同心情下的任务推进

这个图可以放在周视图或反思页里，用来汇总不同心情下的任务情况。

### 推荐字段

| 字段 | 说明 |
|---|---|
| 心情 | 5 级心情，例如“很低落、低落、平静、开心、很开心”。 |
| 覆盖天数 | 这个心情在当前统计范围内出现了几天。 |
| 平均完成率 | 这些天的平均任务完成率。 |
| 启动情况 | 这些天里，有几天至少开始过 1 个任务。 |
| 备注 | 样本很少时提示“只覆盖 1 天，仅作参考”。 |

### 示例表

| 心情 | 覆盖天数 | 平均完成率 | 启动情况 | 适合表达 |
|---|---:|---:|---:|---|
| 😔 很低落 | 2 天 | 43% | 1 天开始过任务 | 需要更多支持的状态 |
| 🙁 低落 | 3 天 | 58% | 2 天开始过任务 | 可以观察启动入口 |
| 😐 平静 | 4 天 | 76% | 4 天开始过任务 | 比较稳定的推进状态 |
| 🙂 开心 | 2 天 | 70% | 2 天开始过任务 | 有推进，也要看任务类型 |
| 😊 很开心 | 1 天 | 100% | 1 天开始过任务 | 只覆盖 1 天，仅作参考 |

## 可视化方案 3：情绪 × 启动能力

这个可能比完成率更有研究价值，因为很多 ADHD 用户最难的是“开始”，不是“知道要做什么”。

### 图表想回答

| 问题 | 例子 |
|---|---|
| 哪些心情下，我比较容易开始任务？ | 平静的 4 天里，4 天都开始过任务。 |
| 哪些心情下，我需要更低门槛的第一步？ | 低落的 3 天里，只有 1 天开始过任务。 |
| 状态不好但成功开始的那天，有什么共同点？ | 都用了很小的第一步，或都从简单任务开始。 |

### 可以使用的数据

| 数据 | 用途 |
|---|---|
| 每日心情 | 判断当天状态背景。 |
| 是否开始过任务 | 计算启动率。 |
| 第一个任务开始时间 | 看是早启动还是晚启动。 |
| 第一步记录 | 看用户是从什么具体动作开始的。 |
| 任务类型或任务名称 | 看哪些任务更容易成为启动入口。 |

## 可视化方案 4：情绪 × 卡住/恢复

这个方向适合放在反思里，不一定第一版就做得很明显。因为“卡住”比较敏感，展示时要更温和。

### 图表想回答

| 问题 | 设计意义 |
|---|---|
| 不同心情下，我更容易在哪些任务卡住？ | 帮用户识别困难场景。 |
| 卡住后，我有没有回来继续？ | 关注恢复能力，而不是只看卡住次数。 |
| 哪些支持方式更容易让我回来？ | 发现有效的低压力策略。 |

### 不建议的表达

| 不建议说法 | 更好的说法 |
|---|---|
| “低落时更容易卡住” | “低落状态下，可能需要更小的下一步。” |
| “你这周卡住很多次” | “这周有几次停住了，但也有几次重新接上了。” |
| “这个状态表现较差” | “这个状态下可能需要更多外部支持。” |

## 可视化方案 5：一周情绪轨迹

这是最轻量的辅助图，可以放在周视图顶部或完成率图下面。

### 示例

```text
😐  🙂  😊  🙁  😐  🙂  😔
5/7 5/8 5/9 5/10 5/11 5/12 5/13
```

### 它适合回答

| 问题 | 说明 |
|---|---|
| 这周整体状态怎样？ | 看见一周情绪起伏。 |
| 有没有连续低落或连续平静？ | 帮助周反思找到入口。 |
| 某天任务变化是否有状态背景？ | 和完成率、活跃节奏一起看。 |

## AI 反思中的使用方式

情绪数据可以帮助 AI 问出更好的问题，但不能让 AI 直接替用户下结论。

### 推荐说法

| 场景 | AI 可以怎么说 |
|---|---|
| 低落但完成率不低 | “那天你记录的是低落，但还是完成了一部分任务。比较值得看看的是，当时是什么帮你开始的？” |
| 开心但完成率不高 | “那天心情记录比较轻松，但任务推进不多。可能那天的重点不一定在任务上，你还记得当天主要被什么占用了时间吗？” |
| 平静且稳定推进 | “这几天记录比较平静，任务也推进得比较稳定。你觉得这种稳定是和时间安排、任务难度，还是环境有关？” |
| 卡住后又继续 | “这里有一次停住后又接上的记录。你当时是怎么让自己重新回到任务里的？” |

### 禁止说法

| 不要这样说 | 原因 |
|---|---|
| “因为你心情低落，所以效率下降。” | 把相关性说成因果。 |
| “开心时你表现最好。” | 像成绩评价，容易造成压力。 |
| “低落是你拖延的原因。” | 带有判断和诊断感。 |
| “你应该保持开心。” | 不现实，也不尊重真实情绪。 |

## 第一版建议

第一版不要做太复杂，建议只做两个模块：

| 优先级 | 模块 | 原因 |
|---:|---|---|
| 1 | 用每日完成率柱子的颜色表示当天心情 | 不额外增加一排符号，图表更干净；用户仍能把完成情况和状态背景放在一起看。 |
| 2 | “不同心情下的任务推进”汇总图 | 能结合覆盖天数、完成率、启动情况，信息更完整。 |

后续再考虑：

| 后续方向 | 适合什么时候做 |
|---|---|
| 情绪 × 启动率 | 当开始任务数据比较稳定后。 |
| 情绪 × 卡住/恢复 | 当卡住记录和恢复记录足够多后。 |
| 情绪 × 活跃节奏 | 当周视图需要更深入解释节奏变化时。 |

## 最终设计判断

情绪可视化最有价值的地方，不是告诉用户“哪种情绪效率最高”，而是帮助用户发现：

> 在不同状态下，我有哪些仍然可用的推进方式？

如果图表能让用户看到“状态不好时我也不是完全不行”“我有一些能帮自己开始的小方法”，那这个情绪可视化就是有价值的。
