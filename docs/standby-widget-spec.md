# 常驻待命 Widget 需求文档

## 一句话定义

始终可见的任务入口，让用户不用打开主界面，就能看到当前任务、切换任务、马上开始或继续。

---

## 解决什么问题

主界面隐藏到托盘后，产品从用户视野中消失。用户不是不想做，而是忘了、懒得开、或者觉得重新进入流程太麻烦。

待命 widget 的作用是：让产品一直"在眼前"，把开始动作放到最近的地方。

---

## 不是什么

- 不是缩小版主界面
- 不负责编辑、排序、管理任务
- 不负责反思、数据可视化
- 不负责 AI 设置、个人资料

这些复杂操作全部留在主界面。

---

## 核心元素（只有 4 个）

### 1. 任务名

显示当前默认任务的标题。一行文字，超长截断。

### 2. 主按钮：开始 / 继续

根据任务状态切换文案：

- 任务有暂停记录 → 显示 `继续`
- 任务没有暂停记录 → 显示 `开始`

点击后的行为和主界面完全一致：

- `继续`：调用现有的 `handleResumePaused`，恢复暂停快照，直接进入执行 widget
- `开始`：调用现有的 `handleFocusTask`，弹出 FocusFlow，走正常启动流程

### 3. 切换按钮

点击后展开任务选择面板，显示今天所有未完成任务。

面板有固定最大高度，默认先露出前几个任务，其余可通过滚轮下滑查看。一天的任务量通常不多，不需要人为截断。

每个候选任务后面跟一个小的 `开始` 或 `继续`（逻辑同上）。

选中后，待命 widget 的默认任务切换为用户选的那个。

### 4. 展开按钮

点击后打开完整主界面。用于所有复杂操作。

---

## 状态逻辑

待命 widget 根据当前任务情况，分 3 种状态显示。

### 状态 A：有暂停中的任务

触发条件：今天的任务列表中，存在 `pausedSession` 不为空的任务。

默认任务：最近暂停的那个任务。

显示：

```
┌──────────────────────────┐
│  整理文献综述            │
│                          │
│  [切换]       [继续]     │
│          [展开]          │
└──────────────────────────┘
```

主按钮文案：`继续`

点击行为：直接恢复暂停快照 → 进入执行 widget。

### 状态 B：没有暂停任务，但有未完成任务

触发条件：今天的任务列表中，没有暂停任务，但有未完成任务。

默认任务：列表中第一个未完成任务。

显示：

```
┌──────────────────────────┐
│  准备明天汇报第一页      │
│                          │
│  [切换]       [开始]     │
│          [展开]          │
└──────────────────────────┘
```

主按钮文案：`开始`

点击行为：进入 FocusFlow 启动流程 → 确认第一步 → 进入执行 widget。

### 状态 C：没有任务

触发条件：今天没有任何任务。

显示：

```
┌──────────────────────────┐
│  还没有任务              │
│                          │
│          [展开]          │
└──────────────────────────┘
```

不显示 `切换` 和 `开始 / 继续`。只保留 `展开`，引导用户去主界面新建。

---

## 切换面板逻辑

点击 `切换` 后，待命 widget 向下展开任务选择面板。

### 候选任务来源

显示今天任务列表中所有未完成的任务，不做数量截断。

排序规则：

1. 有 `pausedSession` 的任务排最前（最近暂停的优先）
2. 其余按任务列表原顺序排列

已完成的任务不显示。

### 面板高度与滚动

- 面板有一个固定最大高度（建议约 200px，大约能直接露出 4~5 个任务）
- 任务超出最大高度时，面板内部可滚轮滚动
- 任务不多时（比如只有 2~3 个），面板高度自适应，不留空白

### 每个候选任务显示

```
任务标题    [继续] 或 [开始]
```

- 有暂停记录 → 按钮显示 `继续`
- 无暂停记录 → 按钮显示 `开始`
- 当前默认任务可加一个轻微的高亮或标记，让用户知道"现在选的是这个"

### 候选任务点击后

- 对应任务变成待命 widget 的默认任务
- 同时直接触发开始 / 继续（和主按钮行为一致）
- 面板自动收起

### 面板底部

固定一个 `打开完整界面` 入口，不随列表滚动。用于新建任务或其他复杂操作。

### 收起逻辑

以下情况面板自动收起：

- 用户点击了某个任务的 `开始` / `继续`
- 用户点击了 `打开完整界面`
- 用户再次点击 `切换` 按钮
- 用户点击了面板外部区域

---

## 默认任务选择规则

每次刷新或启动时，自动选择默认任务：

1. 优先选有 `pausedSession` 的任务（最近暂停的）
2. 如果没有暂停任务，选第一个未完成任务
3. 如果都没有，进入状态 C

用户通过切换面板手动选择后，覆盖默认规则，直到下一次刷新。

## 和现有产品的关系

### 待命 widget 和执行 widget 的区别

|          | 待命 widget        | 执行 widget（现有）  |
|----------|-------------------|---------------------|
| 出现时机  | 没有正在进行的任务时 | 任务开始后           |
| 核心功能  | 选任务、开始       | 执行、计时、接力、求助 |
| 消失条件  | 用户点击开始后      | 任务完成或暂停后      |

两者是**前后接力**关系：

```
待命 widget → 用户点开始 → 执行 widget → 任务结束 → 回到待命 widget
```

### 和主界面的关系

- 待命 widget 负责"开始"
- 主界面负责"管理"
- 待命 widget 的 `展开` 按钮是通往主界面的唯一入口

### 复用现有逻辑

- `开始` 按钮复用 `handleFocusTask` → FocusFlow → 执行 widget
- `继续` 按钮复用 `handleResumePaused` → 恢复快照 → 执行 widget
- 任务数据复用现有的按日期加载机制
- widget 窗口管理复用现有的 `enterWidget` / `exitWidget`

---

## 窗口行为

- 常驻置顶，和执行 widget 一样使用 `alwaysOnTop`
- 位置可拖拽，复用现有的位置记忆机制
- 建议尺寸：宽度和执行 widget 一致（380px），收起时高度约 80~100px
- 切换面板展开时，窗口高度临时增大，面板内最大约 200px，超出部分滚动

---

## 主界面如何进入待命 widget

标题栏原来的"隐藏到托盘"按钮（下箭头 ↓），改为"收起为待命 widget"。

用户在主界面点这个按钮后：

1. 主界面窗口缩小为待命 widget 尺寸
2. 进入 widget 模式（置顶、可拖拽）
3. 前端切换为 StandbyWidget 视图

这样用户的心智模型就是：

- 点收起 → 变成桌面小条，随时能开始
- 点展开 → 回到完整主界面，做复杂管理

托盘双击仍然可以显示/隐藏窗口，作为兜底入口。

---

## 生命周期

```
应用启动
  ├─ 有正在进行的 session → 直接进入执行 widget（现有逻辑）
  └─ 没有正在进行的 session → 进入待命 widget
       ├─ 用户点击 开始 / 继续 → 进入执行 widget，待命 widget 消失
       ├─ 用户点击 展开 → 打开主界面
       └─ 用户什么都不做 → 待命 widget 继续常驻

主界面 → 点标题栏收起按钮 → 进入待命 widget

执行 widget 结束后（完成 / 暂停 / 退出）
  └─ 回到待命 widget
```

---

## 第一版不做的事

- 快速新建任务（留到后续版本）
- 任务编辑（展开去主界面做）
- 优先级显示或切换
- 统计数据
- 反思入口
- 提醒功能
- 复杂动画
