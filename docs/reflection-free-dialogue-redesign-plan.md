# 反思自由对话改造计划

## 目标

这次改造的目标不是简单把原来的三段式流程放松一点，而是把「数据可视化 + AI 反思」改成更像一个懂任务过程的复盘搭子。

AI 需要帮助用户看见三件事：

1. **我今天其实做过哪些努力？**
2. **我用了哪些任务策略，哪些地方接上了，哪些地方接不上？**
3. **下次能不能只试一个很小、低压力的改变？**

对于 ADHD 用户来说，反思不应该只围绕结果好坏，也不应该变成另一项需要认真完成的任务。更理想的体验是：用户每次只需要读一小块内容，就能获得一点被看见、被理解、能继续尝试的感觉。

## 核心问题

当前自由反思模式容易和三段式反思看起来差别不大。主要原因是：

- 对话仍然容易围绕固定步骤运行：开场、Tag、补上下文、给建议。
- AI 有时会一次性输出太多分析，让用户阅读负担变重。
- 数据引用容易变成结果汇报，例如完成多少、卡住多少，而不是帮助用户看见过程中的努力。
- 追问、建议、夸夸、数据分析之间缺少明确的切换判断。
- Tag 仍然可能像分析菜单，而不是自然聊天里的邀请。

因此，这次改造要同时处理三层问题：**对话策略、表达方式、用户动机**。

## 设计原则

### 1. 先看见努力，再分析问题

AI 应该优先从行为数据里找到用户已经做过的努力，而不是直接指出结果不足。

可以被看见的努力包括：

| 行为数据线索 | AI 可以如何解读 |
|---|---|
| 任务没有完成，但开始过 | 启动本身已经发生了，不是完全没动。 |
| 中断后又回来 | 用户有尝试把任务重新接上。 |
| 只推进了很短时间 | 短推进也是推进，尤其在低能量状态下。 |
| 计划了很多但完成少 | 用户不是不在意，而是脑内任务负载可能很高。 |
| 记录了卡住点或求助 | 用户没有硬扛到底，而是在给自己留线索。 |
| 完成了一些小任务 | 小任务也可能是在给大任务铺路。 |

原因：很多 ADHD 用户已经非常容易看到“我没完成什么”，AI 更应该帮助他们看到“我其实如何努力过”。

### 2. 复盘任务策略，而不是评判任务结果

AI 不应该只问“为什么没完成”，而应该帮助用户识别任务策略。

重点分析方向可以包括：

| 策略方向 | 关键问题 |
|---|---|
| 启动策略 | 用户是怎么开始的？靠时间、环境、提醒、压力、兴趣，还是他人介入？ |
| 维持策略 | 哪些条件让用户能多做一会儿？ |
| 中断恢复 | 中断后有没有回来？回来时靠了什么线索？ |
| 降低阻力 | 哪些任务因为被切小、写清楚、放到合适时间而更容易开始？ |
| 情绪保护 | 用户在状态差时有没有保住一点点进展？ |
| 策略迁移 | 今天有用的小方法，下次能不能转移到别的任务上？ |

原因：策略识别能提升自我效能感，比单纯解释结果更能帮助用户形成可复用经验。

### 3. 自由不是随便聊，而是每轮判断用户需要什么

自由对话模式不应该强制走三段式，而应该在每轮回复前判断用户当前状态。

| 用户状态 | AI 当前最应该做什么 |
|---|---|
| 刚进入反思页，还没说话 | 给一个轻观察 + 一个低压力入口。 |
| 用户不知道聊什么 | 给 2-3 个数据分析方向，但写成自然邀请。 |
| 用户主动问数据 | 解释一个最相关的数据现象。 |
| 用户在自责或情绪低 | 先承接情绪 + 具体夸夸，不急着分析。 |
| 用户给出模糊原因 | 只追问一个问题，把困难变具体。 |
| 用户已经说清楚原因 | 给一个轻量建议或小实验。 |
| 用户主动问怎么办 | 可以直接给建议，不强制补上下文。 |
| 用户想结束或回复很短 | 温和收束，不强行继续给 Tag。 |

原因：ADHD 用户的反思能量有限，AI 要减少不必要的流程消耗。

### 4. 每轮只递一小块信息

AI 默认回复应该短、清楚、有重点。

建议规则：

- 默认每轮 **80-120 字中文**。
- 最多 **2 个短段落**。
- 最多列 **3 个点**。
- 每轮最多出现 **2 个数字**。
- 每轮最多问 **1 个问题**。
- 每轮只给 **1 个建议**。
- 加粗 **1-2 个关键词**。
- 可以使用 **0-2 个 emoji**，主要用于标题或轻提示。
- 用户情绪低落时，先夸具体努力，再分析数据。

原因：自由对话是否好用，不只取决于逻辑自由，也取决于用户是否愿意读完。

## 对话模式设计

### 模式 A：努力证据

适用场景：

- 用户刚进入反思页。
- 今日结果不理想，但行为数据里有启动、中断恢复、小推进等痕迹。
- 用户表现出自责、沮丧或低动力。

回复目标：

- 先把用户的努力从数据里捞出来。
- 避免空泛夸奖。
- 不急着给建议。

示例：

```md
✨ **先看到一个努力证据**

今天不是完全没动。左边能看到你有几次试图回到任务上，这个“回来一下”很值得算数。

要不要看看：哪一次其实已经快接上了？
```

### 模式 B：数据轻观察

适用场景：

- 用户问“今天哪里卡住了？”“我今天怎么样？”
- 数据里有明显模式，但不适合一次性展开太多数字。

回复目标：

- 只指出一个现象。
- 少用数字，多说趋势和意义。
- 不把图表复述成报告。

示例：

```md
🔍 **一个小线索**

今天更像是“推进比较碎”，不是完全没有推进。问题可能不在意愿，而在任务开始后不太容易稳住。

你感觉更卡在**开始前**，还是**中断后回来**？
```

### 模式 C：深入追问

适用场景：

- 用户说“就是烦”“不想做”“卡住了”，但原因还不清楚。
- 用户给出了一个重要线索，但还不够具体。

回复目标：

- 只追问一次。
- 把模糊困难变成可观察的任务情境。
- 不连续追问，不审问。

示例：

```md
🧩 **这个线索有点重要**

“一打开电脑就跑偏”听起来不像任务本身太难，更像是进入任务前缺少一个固定入口。

当时你是卡在**不知道先点哪里**，还是卡在**已经点开但接不进去**？
```

### 模式 D：轻量建议

适用场景：

- 用户主动问“怎么办”。
- 用户已经说清楚原因。
- 数据和用户描述能对上。

回复目标：

- 给一个小实验，而不是一套方法。
- 降低失败成本。
- 不把建议说成命令。

示例：

```md
🌱 **下次只试一小步**

可以试一个很轻的实验：离开任务前留一句“回来先做什么”。

目标不是马上进入状态，只是让下次回来时少做一次艰难的重新判断。
```

### 模式 E：方向邀请

适用场景：

- 用户不知道聊什么。
- 当前对话告一段落。
- 有多个可能分析方向，但不确定用户想看哪个。

回复目标：

- 给 2-3 个可选方向。
- Tag 像聊天邀请，不像图表菜单。
- 不要求用户必须选择。

示例 Tag：

```md
可以挑一个轻轻看：

- **找找今天的小努力**
- **看看哪里接不上**
- **给下次留个小入口**
```

### 模式 F：温和收束

适用场景：

- 用户说“先这样”“差不多了”。
- 用户回复越来越短。
- 已经有一个清楚发现和一个小建议。

回复目标：

- 总结一个发现。
- 不继续追问。
- 不强制生成新 Tag。

示例：

```md
💛 **今天先收在这里就好**

今天的小发现是：你不是没有努力，而是中断后需要一个更容易回来的入口。

这个发现已经够用了，下次只试一小步就好。
```

## 夸夸设计

夸夸应该基于具体行为数据，而不是泛泛说“你很棒”。

| 数据现象 | 推荐夸夸 |
|---|---|
| 启动过但没完成 | **启动已经发生了**，这不是零进展。 |
| 中断后回来 | 你有把线重新接上，这个动作很珍贵。 |
| 推进时间很短 | 短推进也是推进，尤其在状态不稳的时候。 |
| 小任务完成 | 小任务不是小成就，它是在给大任务铺路。 |
| 多次切换任务 | 今天可能不是懒，而是脑内任务负载很高。 |
| 卡住时记录原因 | 你在给未来的自己留线索，这很有用。 |

可爱但不空泛的表达：

```md
✨ 今日努力证据 +1：你有回来过。
```

```md
💛 这不是完美推进，但这是一个很顽强的小信号。
```

```md
🌱 今天的小进展可能不显眼，但它确实在给下次铺路。
```

## 可读性规则

### 推荐格式

```md
✨ **一句标题**

一小段观察，只讲一个重点。

一个问题 / 一个小实验 / 一个方向邀请。
```

### 不推荐格式

```md
今天你完成了 3 个任务，未完成 5 个任务，平均专注时间 23 分钟，其中 2 个任务出现卡顿，说明你的任务启动能力和持续能力都有一定问题。建议你下次进行任务拆解、番茄钟规划、环境优化和优先级管理。
```

问题：

- 数字太密。
- 结论太重。
- 建议太多。
- 容易让用户感觉又被评价了一次。

### 数字使用原则

数字只在能帮助用户看见过程时使用。

推荐：

```md
你今天有 **3 次重新回到任务**。这个比完成数量更值得看，因为它说明你不是放弃了，而是在努力接回来。
```

不推荐：

```md
你今天完成率为 37.5%，卡顿率为 25%，平均任务持续时间为 18 分钟。
```

## Tag 改造方向

Tag 应该从“分析菜单”变成“自然聊天邀请”。

| 不推荐 | 推荐 |
|---|---|
| 分析任务完成率 | 今天哪里其实有推进？ |
| 查看卡顿分布 | 哪一步最容易接不上？ |
| 探索时间效率 | 哪些时间更容易动起来？ |
| 任务用时排行 | 哪些任务最花力气？ |
| 卡顿原因分析 | 要不要看看为什么停住？ |
| 策略复用分析 | 有什么小招下次还能用？ |

更轻一点的版本：

- **找找今天的小努力**
- **看看哪里接不上**
- **哪次其实快接上了？**
- **给下次留个小入口**
- **捡一个可复用小招**

## Prompt 改造建议

### 1. 增加每轮意图判断

AI 每轮回复前先判断：

```text
当前用户更需要什么？
- 被看见和鼓励
- 看懂一个数据现象
- 补充上下文
- 继续澄清
- 获得一个轻量建议
- 换一个分析方向
- 结束反思
```

然后只选择一种主要动作。

### 2. 增加努力证据优先级

当结果不理想时，AI 优先寻找：

- 启动痕迹
- 回来痕迹
- 小推进
- 记录卡点
- 求助或使用工具
- 任务拆小

再讨论卡住或未完成。

### 3. 增加可读性硬规则

可以写进 system prompt：

```text
默认回复要短。最多 2 个短段落，最多 1 个问题，最多 1 个建议，最多 2 个数字。
使用 1-2 个加粗关键词帮助扫读。
可以少量使用 emoji，但每轮不超过 2 个。
不要一次性列出大量数据。
不要把反思写成报告。
```

### 4. 增加建议的实验化表达

建议必须写成：

```text
下次可以试一个很小的实验：……
目标不是……，只是……
```

避免：

```text
你应该……
你需要……
你必须……
```

## 测试用例

### 测试 1：用户直接问数据

用户输入：

```text
我今天是不是哪里特别容易卡住？
```

期望行为：

- AI 不要求用户先点 Tag。
- 只指出一个最明显的数据现象。
- 最多问一个问题。
- 不一次性列很多数字。

### 测试 2：用户情绪低落

用户输入：

```text
我今天真的很废。
```

期望行为：

- AI 先承接情绪。
- 基于行为数据找一个努力证据。
- 不马上给长建议。
- 不继续强行推进三段式。

### 测试 3：用户主动要建议

用户输入：

```text
别分析太多，直接告诉我下次怎么避免。
```

期望行为：

- AI 可以直接给一个轻量建议。
- 建议是小实验，不是完整方法论。
- 不强制要求用户补充上下文。

### 测试 4：用户给出具体原因

用户输入：

```text
其实不是任务难，是我一打开电脑就会跑去看别的东西，回来就很难接上。
```

期望行为：

- AI 识别这是“中断恢复/回来入口”问题。
- 给一个具体小实验。
- 可以不生成新 Tag。

### 测试 5：用户不知道聊什么

用户输入：

```text
不知道该看什么。
```

期望行为：

- AI 给 2-3 个自然语言方向。
- Tag 像邀请，不像数据菜单。
- 可以包含一个夸夸方向。

### 测试 6：用户想结束

用户输入：

```text
嗯，先这样吧。
```

期望行为：

- AI 温和收束。
- 总结一个小发现。
- 不生成新的 3 个 Tag。

## 分阶段实现计划

### 第一阶段：只改 prompt

目标：

- 不改 UI 和数据结构。
- 先让 AI 回复更短、更自然、更会夸过程。
- 加入意图判断、努力证据、轻量建议规则。

涉及文件：

| 文件 | 改动 |
|---|---|
| `src/renderer/src/services/ai.ts` | 修改每日反思和周反思 system prompt。 |
| `docs/reflection-ai-flow-and-tag-logic.md` | 同步更新设计说明。 |
| `docs/data-visualization-reflection-prompt.md` | 同步更新 prompt 文档。 |

验证方式：

- 使用上面的 6 个测试输入手动测试。
- 重点检查回复长度、追问数量、建议数量、数字密度和 Tag 生成时机。

### 第二阶段：优化 Tag 文案和生成逻辑

目标：

- Tag 从分析入口变成自然聊天邀请。
- 自由反思模式允许 0-3 个 Tag。
- 收束、澄清、情绪承接时可以不生成 Tag。

涉及文件：

| 文件 | 改动 |
|---|---|
| `src/renderer/src/components/ReflectionChat.tsx` | 检查 `SUGGESTIONS` 解析与展示逻辑是否支持 0 个 Tag。 |
| `src/renderer/src/services/ai.ts` | 调整 Tag 生成规则和文案风格。 |
| `docs/reflection-tag-copy-guide.md` | 扩展自然聊天式 Tag 示例。 |

验证方式：

- 测试用户想结束时是否不生成 Tag。
- 测试用户不知道聊什么时是否生成自然邀请式 Tag。
- 测试用户情绪低落时是否先承接而不是直接给 Tag。

### 第三阶段：增加“今日小发现”收束体验

目标：

- 每次反思自然结束时，AI 可以给一个简短带走物。
- 格式轻，不像报告。

示例：

```md
💛 **今天的小发现**

你不是没有努力，而是中断后需要一个更容易回来的入口。

🌱 下次只试一小步：离开任务前留一句“回来先做什么”。
```

可能涉及文件：

| 文件 | 改动 |
|---|---|
| `src/renderer/src/services/ai.ts` | 增加收束模式规则。 |
| `src/renderer/src/components/ReflectionChat.tsx` | 如需特殊样式，可识别收束内容。 |

### 第四阶段：考虑 UI 层轻量增强

目标：

- 让 AI 回复更易扫读。
- 让夸夸、建议、Tag 更有层次。

可能方向：

- AI 消息支持更清晰的 Markdown 样式：加粗、短列表、emoji 标题。
- Tag 按钮更轻量，文案更像问题。
- “今日努力证据”或“下次小实验”可以有轻微视觉区分。

注意：

- 不要把界面做成很多卡片堆叠。
- 不要让视觉装饰压过任务复盘本身。
- 优先保证文字短、间距舒适、重点可扫读。

## 成功标准

改造后，自由反思应该表现出这些差异：

1. 用户不点 Tag 也能自然聊天。
2. 用户情绪低落时，AI 会先看见努力，而不是直接分析结果。
3. 用户主动要建议时，AI 能给一个小实验，而不是强制补上下文。
4. 用户不知道聊什么时，AI 能给自然、低压力的方向邀请。
5. 用户想结束时，AI 会收束，而不是继续生成三段式流程。
6. 每轮回复更短、更好扫读，有加粗重点，数字不过载。
7. 夸夸具体、基于行为数据，不空泛。
8. 用户读完后能带走一个小发现或一个下次可试的小动作。

## 一句话总结

AI 反思不应该像流程主持人，也不应该像数据报告生成器。它应该像一个懂任务过程的复盘搭子：先帮用户看见努力，再一起找出卡住的机制，最后只递一个下次可以轻轻尝试的小实验。
