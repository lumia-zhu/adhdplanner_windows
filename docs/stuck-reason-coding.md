# P1/P2 卡住原因整理与初步分类

本文基于 `docs/events/events_p1.csv` 和 `docs/events/events_p2.csv` 中的 `stuck.reason` 事件整理，并补充了一些两位参与者数据中未明显出现、但在任务管理场景中较常见的卡住原因。

字段说明：

- **来源**：`系统默认` 指用户选择了快捷原因（`common_chip`）；`自己输入` 指用户在输入框中自行填写（`self`）；`额外想的` 指基于常见任务管理情境补充的候选原因。
- **备注**：只记录涉及哪些参与者；本表不关心具体任务来源，因此相同原因会去重合并。

## 初步分类建议

| 分类 | 说明 | 适合归入的原因 |
|---|---|---|
| 任务理解 | 用户不清楚下一步、材料来源、判断标准、完成标准或优先顺序。 | 不确定下一步、找不到信息、不知道是否需要科学依据、不知道怎样才算做好、不知道先选哪个方向 |
| 任务负荷 | 用户感到任务或步骤太大、太复杂、信息太多，启动门槛高。 | 这一步太难/复杂、不知道从哪开始、内容太多不知道先处理哪一块 |
| 注意力 | 用户被其他应用、信息流、环境刺激或脑中冒出的其他想法拉走注意力。 | 总是被其他事情分心、打开小红书、忍不住想看手机/消息 |
| 情绪/动力 | 用户表达厌学、不想做、抗拒、疲惫、低能量等情绪或动机问题。 | 厌学、不想做、不想学了、太累了、脑子转不动、知道要做但就是启动不了 |
| 情境事务冲突 | 卡住不是因为任务内容本身，而是现实事务、并行任务或外部条件抢占/阻断当前任务。 | 很多事情并行做、饭点想先点外卖、找不到文件、软件打不开、资料不在手边 |

## 面向反思的 AI 回复 flow

这里的目标不是用户一说“卡住了”，AI 就立刻给建议，而是用两轮轻量对话帮助用户补充上下文、促进元认知反思，再给一个低压力、可执行的反馈。

第一轮重点是 **Acknowledge / Data Anchor / Reflection Question** 中按需选择，不强制每类都完整套模板。第二轮给 **Gentle Feedback**，但不要继续追问，也不要让用户在多个选项里再做一次困难选择。

提问要尽量白话、具体到“刚才那一刻”，避免让用户分析抽象原因。问题应该开放，但可以在括号里给最多 2 个短例子，帮助用户知道大概可以回答什么类型的内容。

### 两轮式回复策略

| 分类 | 第一轮目标：促进反思，不急着建议 | 第一轮开放式问题示例 | 第二轮目标：简短反馈和一个低压力建议 |
|---|---|---|---|
| 任务理解 | 帮用户意识到卡住可能来自任务标准、材料来源、下一步定义不清，而不是能力不足。AI 可以按需提到当前任务或当前步骤，但不要堆数据。 | 刚才你看着这个任务时，脑子里第一个冒出来的疑问是什么？（比如不知道标准，或不知道下一步从哪进。） | 帮用户把模糊任务变成一个可判断的小问题。建议要贴合当前任务，例如先确认一个标准、先找一个信息入口、先写下“我需要弄清楚什么”，但这些只是参考，不要固定套用。 |
| 任务负荷 | 帮用户看见任务是从哪里开始变大、变复杂的，避免直接要求“拆小一点”。AI 可以按需提到任务停留时间、已完成微步骤或近期类似卡住。 | 刚才你觉得它变复杂的时候，最先冒出来的是哪一块？（比如材料太多，或要同时想的东西太多。） | 帮用户缩小任务边界，只给一个最小可进入部分。建议要绑定当前任务，例如只看一个文件、只写一句占位、只处理一个材料。 |
| 注意力 | 不责备分心，而是帮助用户回看注意力被带走前发生了什么。AI 可以按需提到用户自己写下的分心原因、当前步骤或近期类似分心记录。 | 刚才注意力被带走前，手上这一步发生了什么？（比如已经有点停住，或旁边有东西一直吸引你。） | 帮用户做一个复位动作，而不是讲大道理。建议可以是关掉具体分心入口、保留任务页面、回到当前任务停留很短时间。 |
| 情绪/动力 | 先承认不想做、厌学、累、抗拒这些感受，不急着拉回原任务。AI 可以按需结合当天任务列表，判断是否有更容易进入的任务可切换。 | 刚才那种“不想做”，你会怎么形容它？（比如累、烦，或说不太出来的一团抗拒。） | 不强行要求回到原任务。建议可以是短休息、换到当天一个具体低阻力任务，或给当前任务留下一个回来点，重点是避免用户完全断掉。 |
| 情境事务冲突 | 承认现实事务会占用注意力，不把它简单解释成拖延。AI 可以按需结合当天计划、当前时间、并行任务、文件/软件等外部条件。 | 刚才除了这个任务，还有什么事情一直在你脑子里占位置？（比如现实事务，或另一个更急的任务。） | 帮用户做一个临时安排。建议可以是先处理现实事务并设置回来点，或先完成当前任务的最小一步再切换，但要结合用户刚才说的具体冲突。 |

### 数据线索使用原则

分类只决定回复方向，不决定必须引用哪条数据。AI 只有在数据能帮助用户理解卡住、降低自责、发现重复模式或做一个更轻的选择时，才引用 **最贴近当前情境的一条**。如果数据只是重复用户已经知道的事，或会让用户感觉被评价，就不要引用。

| 可用数据线索 | 适合什么时候用 | 使用方式 |
|---|---|---|
| 当前任务和当前步骤 | 几乎所有分类都可用，尤其是用户不清楚自己卡在哪里时 | 用一句话点出“你现在卡在什么任务/哪一步”，帮助用户回到具体情境。 |
| 用户选择/输入的卡住原因 | 所有分类都可用 | 复述或转译用户原因，但不要直接下判断；用来连接后面的反思问题。 |
| 今天任务列表和完成情况 | 情绪/动力、情境事务冲突、需要换任务时 | 只提一个事实，例如“今天还有几个任务在排着”，再允许用户选择继续当前任务或换到阻力更小的任务。 |
| 当前任务优先级 | 用户可能需要排序、换任务或处理现实事务时 | 帮用户判断是否值得先处理当前任务，还是先切到更合适的事情。 |
| 当前会话时长和已完成微步骤 | 任务负荷、情绪/动力、用户已经卡了一段时间时 | 让用户看到自己不是“没做”，而是可能需要换策略或降低任务边界。 |
| 近期类似卡住记录 | 注意力、任务负荷、任务理解反复出现时 | 温和指出“这类卡住最近出现过”，帮助用户发现模式，不要让用户觉得被监控。 |
| 近期卡住后成功继续的记录 | 用户低动力、怀疑自己做不到时 | 用来增强自我效能感，例如“之前也有卡住后重新推进的记录”，但不要鸡汤。 |
| 当天另一个更容易切换的任务 | 情绪/动力、情境事务冲突、当前任务阻力过高时 | 第二轮可以直接建议换到一个具体低阻力任务，避免用户完全停住；不要再把多个选项抛给用户选择。 |

### 可读性呈现规则

卡住对话不应像报告或长段建议，而应该让用户一眼看见“我被理解了”和“现在只要做什么”。建议采用低风险文字格式，不强制 emoji 编号：

| 呈现手段 | 使用方式 | 注意事项 |
|---|---|---|
| 空行分段 | 每轮最多 3 个短段，每段只承担一个功能，例如接住、数据锚点、问题或动作。 | 不要把数据、解释、问题和建议挤在同一段。 |
| 重点加粗 | 首轮优先加粗用户要回答的焦点，例如 `**需要的信息**`、`**哪一块**`；第二轮优先加粗时间长度或最小动作，例如 `**1 分钟**`、`**打开资料页**`。 | 每条回复最多加粗 1-2 处，避免满屏重点等于没有重点；不要整句加粗。 |
| 问题和例子分开 | 首轮开放问题单独成段，并在问题里加粗 1 个回答焦点；例子必须另起一段，例如“比如累、烦，或说不太出来的一团抗拒。” | 例子最多 2 个，避免变成多选题。 |
| 灰色引用提示块 | 第二轮可以用 `> 可以先这样试试：...` 轻轻突出最后动作。 | 只用于行动落点，不用于长解释；避免“现在去做”“必须”“只做这一步”等命令语气。 |
| emoji | 默认不强制使用。 | 如果后续测试要加，只能低频辅助情绪或方向，不做固定编号。 |

整体回复应保持 ADHD 友好：第一轮只问一个开放问题；第二轮不给追问，只给一个低压力建议，避免一次给太多信息。AI 始终用“你”称呼用户，不替用户写“我刚才……”。问题要避免二选一，可以给最多两个例子帮助理解，但要保留用户用自己语言回答的空间。

## 初步观察

仅看 P1/P2 的实际数据，去重后两位参与者一共留下 **10 类具体原因表述**。其中 `总是被其他事情分心` 同时出现在 P1 和 P2 中，说明“注意力被拉走”是两位用户都遇到过的共性问题。表格中额外补充的原因不计入该数据统计，只作为后续专家访谈和原型策略设计时的候选情境。

P1 的原因更分散，既有任务复杂和下一步不确定，也有注意力分散、饭点、并行事务等现实情境冲突。这说明卡住支持不应只给“任务拆解”建议，也需要识别用户当下是否被生活事务或外部应用打断。

P2 的原因更集中在学习任务内部和动机阻抗上。一方面是不知道信息来源或写作标准，另一方面是明确表达“不想做/不想学”。这类情况适合让 AI 先降低压力、承认情绪，再帮助用户把任务降到一个很小的可执行动作。

对后续专家访谈来说，可以把这几类原因作为讨论材料：系统默认原因能覆盖“步骤不确定、复杂、分心”等常见问题，但用户自己输入的原因更能暴露真实情境，比如小红书、外卖、并行事务、厌学等。这支持把“卡住了”从静态建议卡升级成可以追问上下文的对话式支持。
