📝 Phase 1: Planning 计划阶段 3 EVENTS
Event 事件名 Description 说明 Fields 字段 Example 示例 Feeds 可视化
plan.brain_dump

Brain Dump
A snapshot of all tasks the user wrote down during their morning brain dump session.
用户打开应用后"倾倒"的所有任务列表快照。 		Captures the raw task pool when the user finishes entering tasks. This is the starting point of the daily planning funnel.

记录用户脑暴池中所有原始任务，是每日漏斗的起点。 		tasks[] Array of {id, title}
taskCount number — Total count of tasks
{ "tasks": [ {"id":"t1", "title":"写数学作业"}, {"id":"t2", "title":"背英语单词"}, {"id":"t3", "title":"整理书包"} ], "taskCount": 3 }
 🎯 漏斗 🔄 进化线
plan.focus_selected

Focus Task Selected
The user chose which macro-task to focus on from the task list.
用户从任务列表中选择了要聚焦执行的宏观任务。 		Records which specific task the user decided to tackle. Measures the transition from "having a list" to "committing to one task".

记录用户决定专注哪个任务，衡量"列表→承诺"的转化。 		taskId string
taskTitle string
taskNote string? — Optional note
{ "taskId": "t1", "taskTitle": "写数学作业", "taskNote": "第三章练习题" }
 🎯 漏斗
plan.first_micro

First Micro-Action Confirmed
The user defined their very first concrete micro-action (ice-breaker step).
用户确定了破冰第一步——第一个具体的微动作。 		The metacognitive interception moment: user must articulate a concrete first step before starting. The source field tracks whether AI scaffolding was used.

元认知拦截点：用户必须说出具体第一步才能开始。source 字段记录是否依赖了AI。 		taskId string
taskTitle string
microAction string
source "self" | "ai_chip"
{ "taskId": "t1", "taskTitle": "写数学作业", "microAction": "翻开课本第58页", "source": "ai_chip" }

exec.micro_started

Micro-Task Started
A micro-task begins execution. Timer starts counting.
一个微任务开始执行，计时器启动。 		Marks the exact moment the user starts working on a specific micro-action. estimatedSeconds captures time perception if user provided an estimate.

标记用户开始做某个微动作的精确时刻。estimatedSeconds 记录用户的时间预估。 		sessionId string
taskId string
taskTitle string
microAction string
estimatedSeconds number?
{ "sessionId": "s_abc123", "taskId": "t1", "taskTitle": "写数学作业", "microAction": "翻开课本第58页", "estimatedSeconds": 60 }
 ⏱️ 时间校准
exec.micro_completed

Micro-Task Completed
A micro-task was finished successfully.
一个微任务成功完成。 		The core data point for time perception calibration. Compares actualSeconds vs estimatedSeconds to measure metacognitive accuracy.

时间感知校准的核心数据。对比实际耗时与预估耗时，衡量元认知准确度。 		sessionId string
taskId string
taskTitle string
microAction string
actualSeconds number
estimatedSeconds number?
{ "sessionId": "s_abc123", "taskId": "t1", "taskTitle": "写数学作业", "microAction": "翻开课本第58页", "actualSeconds": 45, "estimatedSeconds": 60 }
 ⏱️ 时间校准 🏗️ 拆解质量 🔄 进化线
exec.subtask_completed

Subtask Completed
A subtask (child of a macro-task) is marked as complete.
宏观任务下的一个子任务被标记为完成。 		Tracks sub-task level completion within a larger task. Helps measure progress granularity.

追踪大任务中子任务级别的完成情况，用于衡量进度粒度。 		sessionId string
taskId string
taskTitle string
subtaskId string
subtaskTitle string
{ "sessionId": "s_abc123", "taskId": "t1", "taskTitle": "写数学作业", "subtaskId": "st1", "subtaskTitle": "完成第三章填空题" }
 🎯 漏斗
exec.flow_entered

Flow State Entered
User clicked "I'm in the zone, just let me work" — entered flow mode.
用户点击"直接做"——进入心流模式。 		Captures the transition into deep work mode. Records how many micro-steps were completed before flow, to discover the user's "warm-up recipe".

捕捉进入深度工作的转折点。记录心流前完成了几步，帮用户发现自己的"热身配方"。 		sessionId string
taskId string
taskTitle string
lastMicroAction string
completedStepCount number
{ "sessionId": "s_abc123", "taskId": "t1", "taskTitle": "写数学作业", "lastMicroAction": "做第1题画图", "completedStepCount": 3 }
 🌊 心流条件
exec.flow_ended

Flow State Ended
The flow mode session has ended.
心流模式结束。 		Records the duration of flow state and why it ended. Key metric for tracking deep work capacity over time.

记录心流持续时长和结束原因。追踪深度工作能力随时间变化的关键指标。 		sessionId string
taskId string
taskTitle string
flowDurationSeconds number
endReason "task_done" | "exit" | "stuck"
{ "sessionId": "s_abc123", "taskId": "t1", "taskTitle": "写数学作业", "flowDurationSeconds": 1320, "endReason": "task_done" }

stuck.triggered

Stuck Triggered
User pressed the "I'm stuck" button.
用户按下了"卡住了"按钮。 		The moment the user recognizes they're stuck and asks for help. Records how long they've been struggling before seeking rescue.

用户意识到自己卡住并求助的时刻。记录求助前已挣扎了多久。 		sessionId string
taskId string
microAction string
elapsedSeconds number
{ "sessionId": "s_abc123", "taskId": "t1", "microAction": "计算第3题公式", "elapsedSeconds": 180 }
 🧬 卡顿图谱 🔄 进化线
stuck.reason

Stuck Reason Identified
User identified why they're stuck (via AI suggestion or self-input).
用户确认了卡住的原因（AI建议或自行输入）。 		Records the user's articulation of their block. reasonSource indicates if AI helped them name the reason (metacognitive scaffolding).

记录用户对卡点的描述。reasonSource 表示AI是否帮他们命名了原因（元认知脚手架）。 		sessionId string
taskId string
microAction string
reason string
reasonSource "ai_chip" | "self"
{ "sessionId": "s_abc123", "taskId": "t1", "microAction": "计算第3题公式", "reason": "不知道怎么下手", "reasonSource": "ai_chip" }
 🧬 卡顿图谱 📉 AI依赖度
stuck.pivot_offered

Pivot Suggestions Offered
AI generated alternative approaches (detour paths) for the user.
AI 生成了绕路建议供用户选择。 		Records the AI's empathetic response and the alternative micro-actions it suggested. Important for evaluating AI scaffold quality.

记录AI的同理心回应和建议的替代方案。用于评估AI脚手架质量。 		sessionId string
taskId string
empathy string
pivotSuggestions string[]
{ "sessionId": "s_abc123", "taskId": "t1", "empathy": "公式确实容易卡住，换个角度试试？", "pivotSuggestions": [ "先把已知条件列出来", "回看例题找灵感", "跳过先做第4题" ] }
 🧬 卡顿图谱
stuck.pivot_chosen

Pivot Path Chosen
User chose which detour path to take.
用户选择了具体的绕路方案。 		Records the user's strategy decision. pivotSource distinguishes between AI-suggested, self-typed, or resuming the original path.

记录用户的策略决策。pivotSource 区分AI建议、自己输入还是回到原路继续。 		sessionId string
taskId string
chosenPivot string
pivotSource "ai_chip" | "self" | "resume_original"
{ "sessionId": "s_abc123", "taskId": "t1", "chosenPivot": "先把已知条件列出来", "pivotSource": "ai_chip" }

🚪 Phase 4: Abandonment 中断放弃 1 EVENT
Event 事件名 Description 说明 Fields 字段 Example 示例 Feeds 可视化
abandon.exit

Session Abandoned
User exited without completing or going through the stuck rescue flow.
用户直接退出，未走完成或急救流程。 		Records when the user quits mid-task. phase tells us at which stage they gave up (executing, relay, stuck). Important for identifying dropout patterns.

记录用户中途退出。phase 字段说明在哪个阶段放弃（执行中、接力、卡顿）。用于识别退出模式。 		sessionId string
taskId string
taskTitle string
microAction string
elapsedSeconds number
phase string
{ "sessionId": "s_abc123", "taskId": "t1", "taskTitle": "写数学作业", "microAction": "计算第3题公式", "elapsedSeconds": 420, "phase": "executing" }

session.started

Focus Session Started
A new focus session has begun.
一个新的专注会话开始了。 		Marks the beginning of a dedicated focus session. Generates a unique sessionId used to link all subsequent events.

标记专注会话的开始。生成的 sessionId 将串联后续所有事件。 		sessionId string

session.ended

Focus Session Ended
A focus session has concluded.
一个专注会话结束了。 		Summary event for the entire session. Aggregates total duration and completed steps. endReason reveals whether the user finished, exited, or abandoned.

整个会话的汇总事件。聚合总时长和完成步数。endReason 揭示用户是完成、退出还是放弃。 		sessionId string
taskId string
taskTitle string
totalDurationSeconds number
completedMicroSteps number
endReason "task_done" | "exit" | "abandon"
{ "sessionId": "s_abc123", "taskId": "t1", "taskTitle": "写数学作业", "totalDurationSeconds": 2400, "completedMicroSteps": 5, "endReason": "task_done" }

session.macro_completed

Macro-Task Completed
A top-level macro-task has been fully completed.
一个顶级宏观任务被完全完成。 		Records when a major task is done. completedVia reveals the path: finished in flow mode, manually marked, or all subtasks done.

记录大任务完成。completedVia 揭示完成路径：心流中完成、手动标记、或子任务全部完成。 		taskId string
taskTitle string
completedVia "flow" | "manual" | "subtasks_all_done"
{ "taskId": "t1", "taskTitle": "写数学作业", "completedVia": "flow" }

📋 Phase 6: Daily Snapshot 每日快照 1 EVENT
Event 事件名 Description 说明 Fields 字段 Example 示例 Feeds 可视化
daily.leftovers

Daily Leftover Tasks
End-of-day snapshot of tasks that were NOT executed today.
一天结束时未被执行的遗留任务快照。 		Captures the "unfinished business" at end of day. Comparing brain_dump count vs leftover count reveals daily completion funnel efficiency.

捕捉一天结束时的"未完成项"。对比脑暴数量和遗留数量，可以看出每日完成漏斗的效率。 		leftoverTasks[] {id, title, priority}
totalCount number
{ "leftoverTasks": [ {"id":"t2", "title":"背英语单词", "priority":"medium"}, {"id":"t3", "title":"整理书包", "priority":"low"} ], "totalCount": 2 }

completedMicroSteps number
